LUỒNG 1: ĐĂNG KÝ TÀI KHOẢN
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓

  [CLIENT]
     |
     |  POST /auth/register
     |  Body: { email, password, fullName, ... }
     ▼
  [SecurityConfig]  ──── Endpoint này PUBLIC, không cần JWT ────
     |
     ▼
  [AuthenticationController.java]
     |  Nhận UserCreationRequest từ body
     |  Gọi authenticationService.register(request)
     ▼
  [AuthenticationService.java]
     |  1. Kiểm tra email đã tồn tại chưa (UserRepository.existsByEmail)
     |  2. Validate email domain (EmailDomainValidator - DNS lookup thật)
     |  3. Mã hóa mật khẩu bằng BCrypt (PasswordEncoder)
     |  4. Tạo User entity & lưu DB (UserRepository.save)
     |  5. Tạo OTP ngẫu nhiên (6 số)
     |  6. Lưu OTP vào Redis với TTL = 5 phút (RedisOtpService)
     |  7. Gửi email chứa OTP đến người dùng (EmailService)
     ▼
  [UserRepository.java]   →  Lưu xuống MySQL (bảng users)
  [RedisOtpService.java]  →  Lưu OTP vào Redis
  [EmailService.java]     →  Gửi email SMTP
     |
     ▼
  [AuthenticationController]
     |  Trả về ApiResponse { result: "Đăng ký thành công, vui lòng xác thực email" }
     ▼
  [CLIENT]  ← Nhận thông báo thành công


  ── Người dùng nhập OTP từ email ──

  [CLIENT]
     |  POST /auth/verify-email
     |  Body: { email, otp }
     ▼
  [AuthenticationController]  →  [AuthenticationService]
     |  1. Lấy OTP từ Redis theo key = "otp:<email>"
     |  2. So sánh OTP người dùng gửi vs OTP trong Redis
     |  3. Nếu đúng: update User.emailVerified = true, xóa OTP khỏi Redis
     |  4. Nếu sai: trả lỗi INVALID_OTP
     ▼
  [CLIENT]  ← Tài khoản đã được xác thực

LUỒNG 2: ĐĂNG NHẬP & SỬ DỤNG API CÓ BẢO MẬT
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓

BƯỚC 1 - ĐĂNG NHẬP:

  [CLIENT]
     |
     |  POST /auth/login
     |  Body: { email, password }
     ▼
  [SecurityConfig]  ──── Endpoint này PUBLIC ────
     |
     ▼
  [AuthenticationController]
     |  Gọi authenticationService.authenticate(request)
     ▼
  [AuthenticationService]
     |  1. Tìm User theo email (UserRepository.findByEmail)
     |  2. So sánh password bằng BCrypt (passwordEncoder.matches)
     |  3. Kiểm tra email đã xác thực chưa
     |  4. Kiểm tra account có bị khóa không
     |  5. Tạo Access Token (JWT - thời hạn 1 giờ)
     |  6. Tạo Refresh Token (JWT - thời hạn 30 ngày)
     |  7. Lưu Refresh Token vào DB (TokenRefreshRepository)
     |  8. Lưu Refresh Token vào HttpOnly Cookie (CookieUtil)
     ▼
  [AuthenticationController]
     |  Trả về AuthenticationResponse { accessToken, ... }
     ▼
  [CLIENT]  ← Nhận Access Token → lưu vào memory/sessionStorage


BƯỚC 2 - GỌI API CÓ BẢO MẬT (ví dụ: lấy danh sách tài liệu):

  [CLIENT]
     |
     |  GET /documents
     |  Header: Authorization: Bearer <accessToken>
     ▼
  [SecurityConfig] ──── Endpoint này PROTECTED ────
     |
     ▼
  [CustomJWTDecoder]
     |  1. Lấy token từ header Authorization
     |  2. Xác thực chữ ký JWT bằng secret key
     |  3. Kiểm tra token có trong danh sách InvalidatedToken không
     |     (nếu có → token đã logout, từ chối)
     |  4. Kiểm tra hạn sử dụng (exp claim)
     |  5. Nếu hợp lệ → trích xuất userId, roles từ token
     ▼
  [SecurityConfig]
     |  Kiểm tra user có quyền truy cập endpoint này không (SCOPE_USER, ...)
     ▼
  [DocumentController]
     |  Nhận request, gọi documentService.getDocuments(userId)
     ▼
  [DocumentService]
     |  1. Gọi DocumentRepository để lấy danh sách documents
     |  2. Map Entity → DocumentResponse DTO
     ▼
  [DocumentRepository]  →  Query xuống MySQL
     ▼
  [DocumentController]
     |  Wrap vào ApiResponse { code: 1000, result: [...] }
     ▼
  [CLIENT]  ← Nhận JSON danh sách tài liệu


BƯỚC 3 - REFRESH TOKEN KHI ACCESS TOKEN HẾT HẠN:

  [CLIENT]
     |  POST /auth/refresh-token
     |  Cookie: refreshToken=<refresh_token>   ← tự động gửi kèm
     ▼
  [AuthenticationService]
     |  1. Đọc Refresh Token từ Cookie (CookieUtil)
     |  2. Xác thực Refresh Token
     |  3. Kiểm tra có trong DB không (TokenRefreshRepository)
     |  4. Tạo Access Token mới
     ▼
  [CLIENT]  ← Nhận Access Token mới, tiếp tục sử dụng


BƯỚC 4 - ĐĂNG XUẤT:

  [CLIENT]
     |  POST /auth/logout
     |  Header: Authorization: Bearer <accessToken>
     ▼
  [AuthenticationService]
     |  1. Lấy JWT ID (jti) từ Access Token
     |  2. Lưu jti vào bảng InvalidatedToken (blacklist)
     |  3. Xóa Refresh Token khỏi DB
     |  4. Xóa Cookie chứa Refresh Token
     ▼
  [CLIENT]  ← Đã đăng xuất, Access Token cũ không còn dùng được

IV. GIẢI THÍCH CÁC KHÁI NIỆM QUAN TRỌNG
================================================================================

1. JWT (JSON Web Token)
   - Là chuỗi token mã hóa chứa thông tin user (userId, email, roles)
   - Gồm 3 phần: Header.Payload.Signature (phân cách bằng dấu chấm)
   - Server không cần lưu token, chỉ cần xác thực chữ ký
   - Access Token: ngắn hạn (~1 giờ), dùng để gọi API
   - Refresh Token: dài hạn (~30 ngày), dùng để lấy Access Token mới

2. BCrypt
   - Thuật toán mã hóa mật khẩu một chiều (không thể giải mã)
   - Khi đăng nhập: so sánh mật khẩu thô với hash trong DB

3. Redis
   - Là database trong bộ nhớ (in-memory), cực kỳ nhanh
   - Dùng để: lưu OTP tạm thời (có TTL tự xóa), rate limiting

4. Spring Security Filter Chain
   - Mọi request HTTP đều đi qua chuỗi filter
   - SecurityConfig khai báo endpoint nào public, endpoint nào cần JWT

5. JPA / Hibernate
   - Framework ánh xạ Java class (Entity) → bảng Database
   - Repository cung cấp các hàm CRUD sẵn có, không cần viết SQL thủ công

6. DTO (Data Transfer Object)
   - Tách biệt dữ liệu API với dữ liệu trong DB
   - Request DTO: validate dữ liệu đầu vào (@NotBlank, @Email, ...)
   - Response DTO: chỉ trả về những field cần thiết, ẩn thông tin nhạy cảm

7. MapStruct (Mapper)
   - Tự động sinh code chuyển đổi Entity ↔ DTO lúc compile
   - Nhanh hơn reflection, an toàn hơn thủ công

8. Minio
   - Object Storage tự host (tương tự AWS S3)
   - Dùng để lưu file PDF, ảnh chữ ký của người dùng

9. WebAuthn
   - Chuẩn xác thực không cần mật khẩu (vân tay, Face ID, USB key)
   - UsersKeys lưu khóa công khai của thiết bị đã đăng ký

10. ApiResponse<T>
    - Wrapper chuẩn cho tất cả response của API
    - Format: { "code": 1000, "message": "Success", "result": { ... } }
    - code 1000 = thành công, code khác = lỗi (xem ErrorCode.java)
